# Assistant V2 / Conversation UX V2.1 implementation evidence

Normal terminal output now renders models, workers, connectors, Memory, sensitive metadata, Vault status and Mission state as readable text. Read-only commands offer explicit `--json` developer output. Manual preferences are checked with the existing qualified router before selection; a refused selection preserves the previous preference. Shell flags and pasted command prompts resolve locally. `/help` separates shell and interactive commands, and `/mcp` explains the separate shell transport.

Conversation UX V2.1 shows only the user prompt, Airodrom label and natural answer during ordinary chat. It also removes the startup runtime/status dump and worker-oriented tagline. Model/provider and Memory delivery counts, execution state, verification, review and Settlement are available explicitly through `/status`, `/details` and Control Center. `/models` retains truthful underlying model/runtime identity. Conversation instructions identify the assistant naturally as Airodrom. Scoped work retains its previous reporting instructions.

While admission and response execution are pending, a single in-place wave of Unicode dot cells matches the terminal logo's dotted texture and shows measured elapsed seconds. Dots rise and fall within each cell while their density changes across up to twenty cells. A shifting indigo/blue/cyan/mint gradient uses the logo palette, with adapted colors for 256-color and 16-color terminals. The wave remains on one terminal line and does not suggest a completion percentage. It clears before any answer, failure or cancellation; timer cleanup is idempotent, including admission failures and Ctrl-C. No percentages or estimates are invented. Non-TTY and dumb terminals do not animate. `NO_COLOR` removes color; narrow terminals shorten the line without wrapping. Set `AIRODROM_REDUCED_MOTION=1` (or `REDUCE_MOTION=1`) for static dots and gradient with a once-per-second clock.

The terminal mark resolves the unchanged canonical SVG geometry into compact Unicode dot cells: 16 by 7 normally, 12 by 5 when compact, and wordmark-only on very narrow, short or ASCII terminals. Its shading uses the canonical blue, cyan, indigo and mint palette without expanding the silhouette or filling the signature cutouts. Truecolor, 256-color, 16-color and monochrome share the same dot masks. Explicit image mode retains the bundled canonical image.

Canonical confinement, authority, budgets, qualification, erasure, connector injection protection, operator-only sensitive reveal and purpose-bound Keychain semantics are unchanged (ADRs 0005, 0007 and 0010). No schema or permission migration is introduced. Hiding a lifecycle rail does not qualify an optional worker or automatically accept or settle an answer. Use `/accept` only after operator review.

Control Center uses allowlisted canonical event stages for Request, Context, Runtime, Execution, Verification, Acceptance and Settlement. Unobserved stages say so. Activity animates only while execution is observed; no completion percentage or time estimate is invented. Budget consumption is labelled as budget, not completion. Motion stops for review, paused/stale observations and reduced-motion preferences. Conversation detail keeps projected user-visible history on the left and lifecycle operations on the right. The existing current-context projection and generation checks continue to clear stale or forgotten content. Hidden reasoning and internal prompts remain private.

The native menu uses twelve cached template frames at four updates per second while busy. It invalidates the animation timer immediately on an idle observation, uses static approval/waiting/degraded/error states and respects macOS reduced motion. Aggregate status is observed once per second; helper errors do not change control-plane lifecycle. Existing service controls and private opener/lock boundaries remain intact. The terminal fallback samples the canonical SVG as described above.

V2.1 validation uses the focused terminal/conversation/product suite (42 tests), boundary regressions (193 tests), both declared typechecks, public source/syntax checks, package allowlist inspection and redacted source/history secret scanning. A real bounded local OpenCode smoke checks greeting and Airodrom identity without inspecting private Memory or granting Acceptance. Waiting lifecycle checks cover response, failure, cancellation, reduced motion, narrow widths and non-TTY/no-color behavior. The canonical SVG is compared directly with its bundled geometry. These checks follow the existing owner fast-track policy; broad full-suite and hosted runs are not repeated for this presentation pass.

Earlier V2 validation used synthetic data in isolated fixtures. The changed-surface suite covered CLI presentation and parsing, routing refusals, Memory erasure, connector redaction, OpenCode confinement, Pi removal and product projections. Browser checks covered responsive layouts, animated canonical execution, static Acceptance, reduced motion, authorization loss and delayed-response non-resurrection. Native checks exercised actual rendered frames, idle timer cancellation and existing helper safety. Both typechecks, public-source/syntax verification, package sanity and secret tree/history scans passed. The live local OpenCode smoke returned a natural greeting, answered “Your name is Aurora.” after a synthetic remember/restart, and stopped recalling the name after natural forget.

Only OpenCode 2.0.20 with `ollama/qwen3-coder:30b` is live-qualified. Codex/Work and Claude Code remain unavailable; Cursor remains denied. No real account was connected or real personal Memory inspected. The broad GitHub Actions workflow remains manually disabled; no hosted run was used for this UX pass. The existing trigger file is preserved because the Git credential lacks workflow-edit scope. Re-enabling the workflow later would restore its existing push/PR triggers.

Limitations: the adapter returns one bounded visible response, so streaming remains unavailable. Token usage, context capacity and measured price remain unavailable unless observed authoritatively. Model use of selected Memory cannot be measured; selection/delivery is reported separately. Menu idle/busy changes depend on the next aggregate observation. Hidden animation under reduced motion is intentional. No release, tag, registry publication, deployment or production activation is part of this pass.
