# Personal Assistant & Multi-Worker V1

Airodrom handles explicit natural remember/forget/recall before a worker runs. Plain questions create a bounded local conversation; action verbs ask for `/task <mission.json>` with declared scope and verification. Every consequential result still needs independent verification and Acceptance. Conversation factual review uses a compact status rail and `/accept`.

Commands include `/about`, `/version`, `/models`, `/model auto|local|<id>`, `/workers`, `/worker auto|<id>`, `/connectors`, `/connect gmail`, `/gmail status|unread|recent|search|read|thread|summarize|draft-reply|draft`, `/whatsapp status|search|read|draft`, `/remember-sensitive <text>`, `/sensitive`, `/sensitive reveal <id>`, `/sensitive correct <id> <text>`, `/forget <id>`, `/vault`, `/secret`, `/mcp`, `/help` and `/quit`. Interactive `--version`/`--help` resolve locally. Pasted prompt/control-command combinations are refused.

`Remember that my name is Aurora.` saves an ordinary fact. Automatic classification is limited to names and a small set of ordinary preferences. Other durable statements require an explicit Personal/Sensitive choice; keyword absence never proves ordinary classification. `What do you remember about my name?` recalls current ordinary facts without a model. `Forget my name` erases an unambiguous selection; ambiguous matches require an explicit ID. Sensitive facts require explicit sensitivity, remain operator-only, and are absent from automatic recall/context. Reveal sends the value only to the authenticated operator. SQLite storage is private local storage; field-level encryption is not claimed.

For secrets, run `airodrom secret prepare`, then `airodrom secret put [operator|gmail|whatsapp]` in a real terminal. Input is hidden and never accepted as an argument. Output contains an opaque reference only. `airodrom secret forget <ref>` revokes it before deletion. No secret reveal command is exposed. Keychain availability is a host dependency; synthetic tests use an injected host port and never touch real credentials.

Set up Gmail with `airodrom gmail setup <Google desktop OAuth client ID>`, prepare the Keychain helper, restart the owned service, then use `/connect gmail` and complete Google's read-only OAuth consent. Account authorization is not part of synthetic qualification. Search accepts official Gmail query syntax. Read/thread select IDs. `Summarize unread email`, `Anything important this morning?` and `Draft a reply to U-Haul` use bounded selected content; an ambiguous reply requires `/gmail draft-reply <message-id>`. `/gmail draft <body>` previews operator-authored text. There is no remote draft creation/send/archive/delete/label/mark-read activation.

OAuth references are private configuration, and tokens/renewal stay in Keychain. [Gmail list semantics](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list) and [OAuth scopes](https://developers.google.com/identity/protocols/oauth2/scopes) are official protocol references. WhatsApp supports a host-provided official inbound source and signature-checked [Business webhook format](https://developers.facebook.com/docs/whatsapp/cloud-api/webhooks/payload-examples). Personal WhatsApp history and WhatsApp Web automation are unavailable. Send is denied.

MCP tools `submit_mission`, `get_mission_handoff` and `cancel_mission_handoff` use the version-1 packet. Required fields: `version`, `request_id`, `objective`, `mission_class`, `data_class`, `privacy`. Optional constraints, acceptance criteria, reference handles, capability requests, model/worker preference and project/workspace aliases cannot grant authority. Unresolved references and missing WORK templates deny. MCP cannot request personal context. Host-issued sessions isolate clients; a caller can retain its opaque transport session identity and resume with `AIRODROM_MCP_SESSION`, or retain the automatically issued handle in an owner-configured private per-client `AIRODROM_MCP_SESSION_FILE`. Without either handle, transport process loss requires operator recovery; it never authorizes duplicate execution. A fresh identity cannot duplicate or read/cancel another session's request. Restoring a database invalidates old session capabilities; operator inspection remains available.

The Control Center has Conversation and Operations side by side, Models, Workers, Connectors and Sensitive/Vault status. The native helper shows compact model/routing/connector metadata. The terminal mark samples canonical SVG geometry, with ice/mint highlights, a blue face and indigo depth, plus portable color/narrow fallbacks. All model context limits, measured context/tokens and cost remain Unavailable when unobserved. No hidden reasoning is shown. Streaming is unavailable with the current one-result adapter.

Qualification status must come from fresh evidence. OpenCode alone is eligible through the new router. Codex/Work and Claude adapters are supported but not thereby live-qualified; Cursor execution remains denied. There is no unqualified fallback. Alternative-worker live qualification, remote connector mutations and public webhook hosting remain outside this pre-release candidate.

Fresh local full regression: 1,413 tests, 1,411 passed, zero failures, two opt-in environment skips (real MCP acceptance-pair validation and installed tunnel-client schema). Hardening: 801/801. Assistant boundary tests: 42. Browser: 14/14, including responsive views, visible conversation history/lifecycle, natural remember/forget, delayed composer recall and delayed dialog recall after erasure/navigation. Both typechecks and source/package/archive checks passed. Dependency audit found zero vulnerabilities; 38 locked packages use MIT/Apache-2.0 with no install scripts. Directory/history secret scans passed. Native preparation compiled the signed menu in a disposable profile; 11 native helper checks and 16 runtime-removal regressions passed.

Live OpenCode synthetic qualification: 5/5 passed with OpenCode 2.0.20 and local `ollama/qwen3-coder:30b`. The checks prove bounded read/edit, independent repository verification, explicit Acceptance/Settlement, canonical Memory V2 delivery/correction/erasure, process timeout/cancel, natural Aurora persistence across restart and fresh recall/forget, and external MCP canonical progress/result with no private context. No real private Memory was inspected. Live output that failed the strict result contract was refused and left its Mission requiring rework; qualification uses a fresh complete passing run.

Two independent reviews approved the corrected candidate: runtime/authority/router review included fresh 3/3 routing/handoff regressions, 14/14 capability/runtime regressions and 1/1 name-query check; security/privacy review included 85/85 Memory/connector/vault regressions and three final name/context/browser checks. Findings resolved included legacy credential corrections, sensitive subject/family erasure, early worker dispatch bypass, deterministic host routing, session recovery/isolation, connector credential projection, OAuth revocation races and stale UI recall after erasure.

These results do not qualify optional workers, live Gmail accounts, field-level Sensitive Memory encryption, remote connector sends or production activation. Hosted exact-head and post-merge CI are separate merge gates and are reported with the final commit identity.
