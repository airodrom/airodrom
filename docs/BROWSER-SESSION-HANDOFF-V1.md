# Authenticated Browser Session Handoff V1

Use `airodrom`, then:

> I'm already logged in to Monarch; inspect my account

Or use `/research login https://app.monarch.com/` for the deterministic dedicated-profile flow. Choose dedicated login or cancel. Normal Chrome authentication is not inherited. External Chrome attachment is unavailable in V1; supported remote debugging of separate profiles exists, but arbitrary local endpoint ownership has not been qualified.

Natural operator requests also support “Airo, open an authenticated browser session for app.monarch.com. I will sign in manually.” and “Airo, explore my Monarch account and compare it with Arecibo.” Both offer the dedicated manual-login workflow before creating a Mission or opening a browser. A follow-up such as “I will sign in manually” may reuse the last operator-selected research URL in the same host-issued conversation for five minutes. This context grants no consent, comes from no model/history/connector text, and clears on unrelated or service-screened rejected input. A locally refused terminal submission does not refresh or clear host context; its five-minute expiry and fresh domain consent still apply. Bare address tokens are validated whole, including scheme, userinfo, port, query, fragment and path; safe substrings are never salvaged. Multiple targets require clarification; the origin is shown again at consent.

Normal terminal research output presents plain sections, bullets, readable URLs and evidence labels. `/research report [mission-id]` displays the independently verified report again; add `--json` for its canonical Markdown and structured evidence. Display formatting does not modify canonical report digests, references, privacy projection or Acceptance. Fixed private navigation labels keep feature comparisons unknown until public capability evidence exists.

A visible, isolated Chrome profile opens only after explicit authorization. Sign in manually and complete MFA in that window, then confirm hand-back in Terminal. Airodrom begins read-only investigation within the signed three-minute Mission budget. Each future reuse requires fresh consent. Browser profile storage stays private and local; no password or cookie is imported or exported by this workflow.

The report retains fixed navigation feature labels only. Private screenshots, financial text, raw network metadata, downloads, exports, settings changes, payments, account mutations and external model calls are disabled. Current Arecibo baseline files and HEAD are verified using existing host registration. Account navigation labels are observations; underlying functionality remains unverified and inaccessible areas remain unknown. Recommendations cannot implement themselves.

V1 intentionally blocks all redirects, extra domains, query parameters, encoded paths and POST data APIs such as GraphQL. Only fixed same-origin login POST endpoints are admitted during human login. A competitor requiring OAuth, external APIs or unrecognized endpoints may fail to sign in or render. Real Monarch login has not been qualified. On an MFA/CAPTCHA challenge during automated investigation, inspection stops safely; complete human takeover through a fresh consented Mission. Cancellation and deadline closure preserve the dedicated profile and quarantine uncertain termination.

## Compatible routing and terminal repair

The installed scanner reused conservative display redaction: `session <word>` treated “for” in “browser session for …” as a credential. Operator screening now checks credential shapes across the full submission before normalizing only a valueless browser-session noun with a validated address/context token, or a complete final clause describing human password entry in the browser. Unknown trailing clauses remain screened. Safe sentence punctuation is separated only after whole-address validation. Assignment values, unknown session values, credential-bearing URLs, private paths, userinfo, query parameters, tokens and suspicious mixed submissions still fail closed. Display/provider redaction remains conservative. Screening precedes browser routing; no general URL exemption or secret-screen disablement was added.

The parser previously missed natural account phrasing and retained pending context only for an unanswered URL request. Authenticated/manual-login requests now return the existing `research_session` offer, and fresh operator domain context supports login follow-ups. Terminal consent still detaches ordinary readline, drops pasted input, requires an explicit choice and binds hand-back to the selected waiting Mission. Signed deadlines, exact origins, redirects, MFA/CAPTCHA takeover, private profile integrity and read-only enforcement retain ADR 0015 semantics. Mixed exports, financial actions and settings mutations are refused at routing as well.

Terminal output previously wrote `report.markdown` directly. A presentation-only formatter removes generated Markdown wrappers and exposes structured output only through the explicit developer option. A focused check also reproduced an existing main-branch report regression: private navigation labels could inherit a feature comparison status from the Arecibo baseline. The report now keeps these comparisons unknown, preserving navigation observations and provenance without claiming product functionality or a feature gap.

This repair is compatible with accepted ADRs 0011, 0013 and 0015; no authority, schema, dependency or profile migration is required. Qualification uses local focused routing/consent, secret/mixed-input, domain/redirect, handoff/cancellation/deadline, report/redaction checks, one synthetic visible-browser smoke, both declared typechecks and package inspection. Real Monarch authentication is not tested. Independent runtime/authority and security/privacy review disposition is recorded with the final source revision in the pull request. The candidate workflow remains manually disabled; no hosted CI, release, tag, publication, deployment or production activation is authorized.
