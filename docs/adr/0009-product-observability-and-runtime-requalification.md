# ADR 0009 — Private product observability and bounded host requalification

Status: Proposed; independent review and integration gates pending. Compatible with ADRs 0005, 0007 and 0008.

Airodrom's CLI, local Control Center and native menu share host-observed health categories. Overview, timeline, event-feed, native-summary and mutation receipts expose only bounded identifiers, enums, counts and timestamps. Prompts, reasoning, memory text, evidence output, internal grants, paths, environment, process arguments and credentials are excluded. Explicit authenticated `/api/product/memory` retrieval has a separate operator-display contract: at most 20 current normal-sensitivity personal reference records, safe subject/content and non-content canonical freshness. Memory text is never fetched automatically into overview/feed/menu. Navigation, visibility loss, authorization loss, failed reads, canonical generation changes and mutations clear client text and invalidate outstanding Memory requests. Existing authorized task surfaces retain their separate operator contract. UI visibility never grants authority.

The browser uses authenticated same-origin incremental cursor polling, four pages of at most 200 events per cycle and 500 retained safe events. Hidden pages and paused feeds stop polling. In-flight reads are invalidated on filter, pause and visibility changes. Daemon instance changes reset the cursor. Failures back off to 30 seconds; authorization loss requires reopening private discovery. The menu reads a compact host summary every five seconds with one request in flight and bounded native command deadlines.

Run start events declare worker versus independent verifier roles. OpenCode execution starts are observed at process spawn and bound to the canonical ContextPack run. Delivery is recorded only after a successful confined result and current-context revalidation. Delivery does not prove model use. Acceptance and Settlement events follow their actual durable records and distinguish rework. Checks on old runs/revisions are historical, never current acceptance evidence. Phases have no percentage weights; unknown completion denominators remain indeterminate or paused.

A stale host Node pin can be repaired only when the exact qualified OpenCode digest/model/platform/version and Seatbelt artifact remain unchanged. The current owned Node must meet the supported 22.x engine floor. An exclusive private qualification lock serializes a fresh disposable real sandbox probe. Current executable identities, stopped ownership and the unchanged private pin document are checked again before atomic replacement. Unsupported drift preserves the old pins. No changed OpenCode bytes are trusted because of a version string.

The local CLI can stop its own idle service to repair this supported drift. Active runs, quarantined leases, foreign source identity and unverifiable ownership prevent repair. Confirmed-dead discovery can be reconciled without deleting user data; malformed or live ownership remains fail-closed. Startup uses absolute deadlines and cancellation reaches the qualification probe and lock cleanup.

The native helper uses an original vector template mark, private Launch Services discovery and a fixed private Terminal launcher. Start/stop/restart retain the existing owner/PID/lock guards. Quitting or crashing the helper does not stop the service. Menu compilation uses a private staged bundle; it installs no LaunchAgent or unrelated persistence. Existing optional LaunchAgent installation remains explicit and governed separately. Local npm linking and helper preparation are not package publication or production activation.

Validation includes privacy canaries in HTTP reads/receipts, canonical lifecycle/role mapping, correction/erasure invalidation, truthful progress, concurrent and interrupted repair, native private-file boundaries, browser focus/reduced-motion/narrow layout, full repository checks, two independent reviews and exact-revision hosted CI. PRE-RELEASE remains; no release, tag, registry publication or deployment is authorized.

Restore qualification also uncovered a supersession gap: a pre-correction backup could revive an old record after its replacement was forgotten. Both canonical constructors now preserve source supersession before any read/index/context exposure, keep missing successors inactive without fabricating records or relaxing foreign keys, validate current identity/scope/payload/policy and bind freshness to non-content disposition. Later corrections invalidate recovered copies even without a new erasure marker.
