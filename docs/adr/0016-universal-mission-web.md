# ADR 0016 — Universal governed Mission web

Status: Accepted under the owner’s implementation request; merge requires both independent local reviews of the exact candidate commit.

Extends accepted ADRs 0013 and 0015. Any qualified local Work Mission may request typed public web actions through CapabilityBroker. Ordinary conversation retains its conversation-first path. Web policy does not widen worker sandbox networking, filesystem permissions, provider routing, Mission authority, verifier criteria or Acceptance/Settlement. Eligible Missions need explicit current internet/data-read authority and a local host/OpenCode route. A read-only or offline authority ceiling requires a fresh operator-registered Mission before web access can be enabled.

Operator commands grant on/off/all policy per Mission. The immutable Mission and current canonical Run are intersected with a separate signed, expiring public-only grant in the existing control-plane SQLite store. The seal binds the Mission envelope, initial sources, optional public search query and budgets. All grants expire within three minutes. On permits exact source origins. All permits bounded public discovery from verified evidence links. Arbitrary worker URLs, private accounts, login, cookies, bodies, selectors, scripts, mutations, payment and private documents are absent from the typed port. Unknown domains in on mode stop for operator scope approval. Revocation/cancellation abort owned operations. Content-derived grant seals and evidence hashes use existing retention/erasure classifications; evidence remains inside canonical task session storage.

Natural search and multi-site explorer requests offer native operator consent. Qualified coding Missions automatically detect web needs before dispatch. The host collects approved evidence before handing bounded public reference context to OpenCode. OpenCode can request additional typed evidence in its result, with two bounded rounds and no file changes during an evidence-request response. The broker, host provenance checks and current authority make the decision. Execution workers retain denied direct web/browser tools. Independent evidence verification, factual owner review, Acceptance and local Settlement remain separate.

Search uses a fixed host-approved adapter. DuckDuckGo HTML is implemented but not enabled: the live unauthenticated probe on 2026-10-07 required human verification. Missing/unavailable providers fail honestly and no source result is invented. Public HTML/text documents use bounded host transport; PDF extraction fails explicitly because no pinned local parser/sandbox is currently qualified. No converter is installed automatically.

Monarch repair: metadata-only pre-login observation found Playwright route aborts for static.monarch.com assets and a public monarch.com → www.monarch.com root redirect. Dedicated login can explicitly consent to a fixed verified catalog of those exact resources/roots. There are no wildcard subdomain grants or external POST rules. Request-stage and response-stage CDP guards check every hop before network follow-up; redirect budgets and narrow methods remain enforced. Other identity services, GraphQL POST and challenge flows remain blocked. CAPTCHA/MFA require the operator; no bypass or live account qualification is claimed. After hand-back, external root navigation and login POST are denied again. Normal Chrome profiles, credentials and account screenshots are never imported or exported.

Compatibility: additive typed capability and canonical tables, no dependency update, no worker sandbox relaxation, no profile migration. Historical Missions have no web grant. Gmail, Vault, Memory, menu/fish/service behavior and unrelated work stay under their existing contracts. The required local validation and two independent review dispositions are recorded in the PR; hosted workflows remain disabled. No release, publication, deployment or production activation is included.
