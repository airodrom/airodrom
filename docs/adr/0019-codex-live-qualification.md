# ADR 0019: Codex live qualification with a signed bundle snapshot

Status: Accepted under the owner's focused implementation request, subject to two independent local boundary reviews. Narrows and repairs the Codex transport in ADR 0018; no new execution authority.

Codex CLI 0.160.1 supports noninteractive `exec --json --output-schema`, ephemeral sessions and explicit exclusion of user configuration and rules. The app-bundled macOS executable is signed together with its Info.plist. A bare executable copy is killed by AMFI before startup. The host now copies only the executable, Info.plist, signature resource and provisioning profile into a disposable bundle, checks types/ownership/size, verifies its existing signature without re-signing, and checks the executable against the qualification hash.

The supported `features.code_mode_host=false` setting prevents Code Mode child startup; disabling `code_mode` alone does not. Tools, hooks, plugins, skills and web search remain disabled. The structured parser permits only the exact pinned diagnostic saying the host is disabled, alongside its existing agent-message/reasoning events. Other error items, tool events, unknown events and vendor failures still deny execution.

The confined CLI cannot load native TLS roots reliably. The host extracts only validated PEM certificates from the root-owned public macOS CA bundle into a read-only disposable file and supplies it through supported `CODEX_CA_CERTIFICATE`. No custom root, TLS bypass or credential is introduced. The CA digest joins binary/version/model/policy in signed qualification and returned provenance; drift blocks admission and host writes. The operating-system sandbox still denies forks, arbitrary child execution, source-repository reads, secrets beyond Codex's existing read-only auth alias, and direct network access. The exact-host/public-DNS/SNI proxy and its time/byte/connection limits are unchanged.

Template secret screening still examines all text, including digit strings, and all numbers except the independently bounded numeric authority expiry. A future authority timestamp cannot accidentally be rejected merely because it passes Luhn. This fixes a nondeterministic handoff refusal without permitting credentials in public content or exempting other numeric fields.

OpenCode remains the default live local worker. Codex is opt-in for explicitly public scoped proposals, with host application, independent protected tests and explicit Acceptance/Settlement. Qualification does not grant Mission authority. Claude Code remains unqualified and Cursor denied. A successful local authenticated MCP proof does not establish ChatGPT connector exposure. The owner must refresh the existing connector's tool schema before its new Mission tools can be used from ChatGPT.

Validation is critical local containment, credential non-leakage, signed snapshot/CA drift, scoped host writes, cancellation/late-output/lease cleanup, verification/Acceptance/Settlement, authenticated MCP, changed status UI, typechecks and package/source checks. The opt-in live probe uses an isolated public repository and private disposable state. Repository Actions and workflows remain disabled; no hosted agents, publication, release, deployment, private-account research or Arecibo work is authorized by this change.
