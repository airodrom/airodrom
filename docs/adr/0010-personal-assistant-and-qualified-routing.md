# ADR 0010 — Personal assistant and qualified model/worker routing

Status: Proposed; independent review and exact-revision qualification are integration gates.

Airodrom continues to own authority, canonical Memory, scopes, leases, verification, Acceptance and Settlement. Operator input is parsed deterministically before dispatch. Explicit remember, forget and recall use host Memory V2 operations. WORK verbs request a scoped registered Mission rather than inferred filesystem or external permissions. Conversation remains the existing signed bounded local profile: no worker tools, filesystem access, external inference or implicit mutations. Factual review remains explicit Acceptance; structural evidence alone does not settle a conversation. The response prose has a separate compact lifecycle rail.

Model and worker preferences are separate. The canonical local model records its provider, locality, compatible worker, permitted data classes, runtime evidence, model digest and expiry. OpenCode readiness checks its pinned runtime and the actual Ollama model digest. Expired, changed, unavailable, unknown or incompatible selections fail closed. Context limits, measured usage and price remain unavailable without authoritative observations. A discovered executable or compiling adapter is not live qualification. Codex/Work and Claude remain supported adapters but unavailable through the new qualified router until independently qualified; Cursor remains denied. Deterministic host plans retain existing host execution and verification.

Sensitive Memory is operator-only canonical personal storage with sensitivity metadata and opaque subjects. Explicit reveal needs the current record ID and authenticated operator endpoint. It never enters the worker context. Sensitive correction/forget uses canonical family erasure. Ordinary corrections cannot silently turn into health/financial/credential facts. SQLite has no new field-level encryption guarantee. Credential-like content is rejected from all ordinary/sensitive write and correction paths. The Secret Vault uses a separate host Keychain port with hidden input, opaque UUID references, purpose binding, private pipes, durable dispositions and independent Keychain revocation markers. Workers receive no secret values. Restored vault views require current independent original dispositions, remain read-only, and recheck freshness after resolution. Copying an old local home into production is unsupported.

External handoff is versioned request data, never an authority grant. MCP clients receive separate host-issued sessions; concurrent initialization coalesces. An opaque session can be resumed against current canonical session metadata. Reusing a request from another session denies duplicate execution. A handoff's entire packet is idempotency-bound. External packets cannot opt into Personal Memory; only authenticated operator submissions can request it. WORK needs a preconfigured host template with immutable workspace, capabilities and registered tests; requested review criteria can only add review restrictions. Client status/cancel is bound to the originating session. Supported isolated database restore drops old handoff session capabilities and does not reactivate them.

Gmail uses owner-configured desktop OAuth, PKCE, exact gmail.readonly scope and a pinned loopback callback. OAuth tokens and refresh tokens live in the host Keychain port. Read requests use only the official Gmail origin, GET, no redirects and bounded response/content. No Gmail account is connected during qualification. Selected mail summaries and reply drafts enter a fresh confined conversation with no Memory or tools; message instructions stay untrusted data. Drafts are previews, not remote drafts or sends. OAuth account access is an explicit operator action.

WhatsApp is an official Business Cloud API foundation: bounded text from a host-authenticated source and signature-checked webhook extraction. No public webhook listener, personal WhatsApp Web automation or personal-history import is activated. Replies are local previews. Sending and other connector mutations remain denied until a separate canonical capability and approval adapter is implemented and qualified.

Terminal, authenticated conversation view, models/workers/connectors views and native summary show observable metadata and visible responses, never hidden reasoning. Conversation history is fetched only in the conversation view, revalidated against canonical context and cleared on navigation, visibility/auth loss or generation changes. The adapter currently returns one bounded response; streaming is explicitly unavailable.

Compatibility: canonical schema adds only non-content opaque handoff-session IDs and timestamps. Personal Memory V2 is preserved; no real payload is inspected for qualification. Existing fixture adapters remain explicitly synthetic. Distribution stays PRE-RELEASE. No release, tag, registry publication, deployment or production activation is authorized.
