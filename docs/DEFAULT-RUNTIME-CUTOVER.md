# Default runtime cutover

New general Missions without `preferred_agent` freeze `opencode`, `route_mode: default`, no fallback agents, and a bounded local-only dispatch policy. Both canonical and compatibility routing honor that stored choice. OpenCode availability requires the qualified CLI 2.0.20 on macOS and the local Ollama model. Unavailability, missing scope, stale context or an incompatible policy stops for review without choosing another runtime.

Pi remains explicit compatibility/rollback. Operator-registered typed file plans and independent verification still use Pi. Claude Code remains an optional supported fallback where an explicitly frozen external policy permits it. Work/Codex is optional external/live-unqualified, Cursor experimental, and generic Cloud unsupported. Existing automatic Mission envelopes retain their prior taxonomy semantics; saved explicit runtime identities never migrate.

`src/default-runtime.js` defines the default once. Host composition accepts `defaultRuntime: 'pi'` for isolated rollback; the service reads `AIRODROM_DEFAULT_RUNTIME` for separately authorized operator configuration. This pass does not modify a running service. No schema or data migration is required. A source reversal preserves frozen Mission and task identities, Memory V2 truth and Acceptance/Settlement. A Pi default does not expand Pi's allowed Mission capabilities: general coding beyond qualified typed plans still requires a qualified route.

The legacy plain-prompt API now creates an OpenCode identity by default and requires a bounded registered Mission for execution. For the existing Pi RPC compatibility flow, explicitly set `executionAgent: 'pi'` in the host/UI API or `execution_agent: 'pi'` in MCP `create_task`. Reasoning-only and deterministic broker modes remain provider/control-plane operations. Fixed Active Chat and Level 1 compatibility fixtures retain their explicit Pi identities. A bare prompt cannot invent a Mission scope or silently fall back to Pi.

Every dispatch stores its selected route, task identity and run agent. OpenCode additionally records pinned executable/version, disposable execution identity and verified termination. Runtime selection conveys no authority; independent repository verification precedes Acceptance and local Settlement for either runtime.

Completed Mission erasure retains only allowlisted review outcomes, validated result relay identities, the Mission revision foreign key and selected runtime identity. Unknown outcomes or receipt shapes fail closed. Content and cache copies remain erasable.

The cutover tests cover default and explicit routes, unavailable policy, persisted identities, isolated rollback, minimum synthetic Memory V2 context, correction, canonical erasure, denied stale packs/session reuse, Pi non-delivery and runtime-independent Acceptance/Settlement.
