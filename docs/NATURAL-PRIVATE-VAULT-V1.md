# Natural Private Vault V1

The terminal owns identifier capture, confirmation and disclosure. `Hi Airo, let's save my mailbox number 818.` offers a confirmed private-identifier save in the existing Keychain Vault under `Mailbox number`. `What's my mailbox number?` performs a deterministic lookup and requires fresh operator confirmation before terminal disclosure. Neither operation calls an inference provider, sends the value to the local service, nor adds a conversation turn. Only mailbox, locker and parking-space numbers accept inline numeric identifiers in V1. Credential requests still use the separate reviewed no-echo `/vault` workflow; pasted credentials are refused.

`/secret` and `/secret list` show operator metadata. `/secret search <label>`, `/secret reveal <label>`, `/secret remove <label>` and `/secret rename <label> to <new label>` accept readable labels. Search ambiguity requires one selection. Saves and renames reject case-insensitive label collisions instead of overwriting. Removal requires confirmation, clears label metadata and permanently revokes the canonical reference. Passwords, keys, tokens and recovery codes cannot be revealed by this workflow, including after renaming. Connector credentials never appear in the operator list. Existing unlabeled entries retain generated recoverable names; `/vault` also supports selection by number.

Labels contain words, spaces and basic punctuation; numeric values and control input cannot be labels. Labels are private local metadata. Values use the existing Keychain host port with private pipes; shell arguments contain only the operation and opaque reference. Version-1 disposition files remain compatible. Restored readers use current source classifications, names and dispositions; they are read-only and cannot resurrect revoked entries. No credential-purpose changes or automatic migrations are introduced.

Unknown save requests ask for Personal/Sensitive/Vault classification and direct the operator to the explicit existing workflow. V1 does not silently reclassify or store an ambiguous fact. Noninteractive streams, browser chat and direct service requests cannot save or reveal identifiers. The operator terminal necessarily displays a value after confirmed reveal; the implementation takes no screenshots or telemetry of that output. Terminal scrollback and user-created captures are outside Airodrom's retention control.

Governed browser research is **unavailable**. Natural research/navigation requests receive that status without navigating, creating a Mission, using credentials or inventing evidence. Public-page navigation, account authorization, human MFA takeover, domain policy, screenshot redaction and feature-gap/cost reports are unimplemented and unqualified. Arecibo comparison is explicitly unverified. Recommendations are never implemented automatically. This gate must remain closed until the complete capability is independently reviewed and qualified.

Validation uses synthetic identifiers and isolated disposition files, including the real Keychain helper with random synthetic references where available. Live personal Memory, Vault entries and Gmail authorization are preserved. Fixture checks do not establish live account or browser qualification. Integration follows [project governance](../GOVERNANCE.md) and [ADR 0012](adr/0012-natural-private-vault-and-research-gate.md).

## Vault UX V1.1

Compatible repairs to ADRs 0011 and 0012 keep Keychain, classification, purpose binding and revocation authoritative. Nonsecret choices and Yes/No confirmations are visible. `Confirm [y/N]` requires a fresh `y` or `yes`; No, Enter, Ctrl+C, aborted input, unsupported input, competing readers and non-TTY streams fail closed. Selection uses numbered keyboard choices; invalid choices explain cancellation. Choices validate every intermediate prefix before echo, reject multiline/bracketed pasted confirmation, discard queued input between prompts and restore terminal mode/listeners.

The operator journey is:

1. `Hi Airo, let's save my mailbox number 818.` shows `Mailbox number`, `Value: 818` and its private-identifier classification in the operator terminal, then asks to save. A valueless request asks for a hidden number before the numeric preview. Invalid/credential input in that field is refused without echo.
2. A fresh visible Yes stores the identifier. No or Ctrl+C changes nothing. A case-insensitive duplicate explains how to rename/remove the existing entry without overwriting it.
3. After process restart, `What's my mailbox number?` resolves the named entry and requires a fresh reveal confirmation. The prompt explains terminal scrollback. Only an authorized identifier reveal displays `818`; operation receipts, model/service payloads and disposition metadata contain no value.
4. `/secret list` and `/secret search <label>` display labels and classifications without reading Keychain values. Empty and missing states offer the next command. Ambiguous matches require a visible numbered selection.
5. `/secret rename <label> to <new label>` previews the two labels and requires confirmation. Collisions preserve both entries. `/secret remove <label>` explains permanent reference revocation and requires confirmation. A label/reference/classification changed during either prompt is refused; stale/revoked entries offer a fresh list/status check.
6. `/vault` or a valueless natural password/API-key save request opens the credential menu. Visible choices select type and a predefined Personal, Work or Service label. Preset labels avoid accidental credential paste into a free-form label field. Hidden value capture precedes a separate visible Yes/No save confirmation. A credential remains a credential after rename and can only be used by its purpose-bound approved host capability; this workflow cannot reveal it.

The related account-capability guide also uses visible named credential selection and fresh Yes/No authorization, rechecks selected metadata, and sends only purpose-bound opaque references. No live account login is part of this Vault acceptance. The historical browser-unavailable gate above is superseded by [ADR 0013](adr/0013-governed-browser-product-research.md); this repair preserves that separately reviewed feature.

Ordinary terminal editing uses a private output sink and disables readline history. The complete submitted line is screened locally before display or dispatch, preventing split token/paste and cursor-edit leaks before credential recognition. The startup prompt explains that questions appear after Enter; Yes/No and menu choices appear while typing. Recognized credential requests are refused locally without a service/model payload. Classification is not a universal detector of every arbitrary password: credentials must use the explicitly hidden Vault field, and operator-created metadata labels must not contain values. Shell input before Airodrom starts, screenshots and unmanaged physical captures remain outside its control.

Vault prompts are static, concise text with no animation, color dependency, UUID-first identity or raw JSON. They wrap naturally in narrow terminals, support no-color/reduced-motion configurations and preserve the logo and fish/wave renderer. Control Center distinguishes credentials (never revealed there), operator-confirmed private identifiers and Sensitive Memory. It directs named operations to the authenticated terminal; ordinary Memory retains its existing canonical authorization/erasure controls.
