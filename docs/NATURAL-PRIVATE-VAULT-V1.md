# Natural Private Vault V1

The terminal owns identifier capture, confirmation and disclosure. `Hi Airo, save my mailbox number 818` offers a confirmed private-identifier save in the existing Keychain Vault under `Mailbox number`. `What's my mailbox number?` performs a deterministic lookup and requires fresh operator confirmation before terminal disclosure. Neither operation calls an inference provider, sends the value to the local service, nor adds a conversation turn. Only mailbox, locker and parking-space numbers accept inline numeric identifiers in V1. Credential requests still use the separate reviewed no-echo `/vault` workflow; pasted credentials are refused.

`/secret` and `/secret list` show operator metadata. `/secret search <label>`, `/secret reveal <label>`, `/secret remove <label>` and `/secret rename <label> to <new label>` accept readable labels. Search ambiguity requires one selection. Saves and renames reject case-insensitive label collisions instead of overwriting. Removal requires confirmation, clears label metadata and permanently revokes the canonical reference. Passwords, keys, tokens and recovery codes cannot be revealed by this workflow, including after renaming. Connector credentials never appear in the operator list. Existing unlabeled entries retain generated recoverable names; `/vault` also supports selection by number.

Labels contain words, spaces and basic punctuation; numeric values and control input cannot be labels. Labels are private local metadata. Values use the existing Keychain host port with private pipes; shell arguments contain only the operation and opaque reference. Version-1 disposition files remain compatible. Restored readers use current source classifications, names and dispositions; they are read-only and cannot resurrect revoked entries. No credential-purpose changes or automatic migrations are introduced.

Unknown save requests ask for Personal/Sensitive/Vault classification and direct the operator to the explicit existing workflow. V1 does not silently reclassify or store an ambiguous fact. Noninteractive streams, browser chat and direct service requests cannot save or reveal identifiers. The operator terminal necessarily displays a value after confirmed reveal; the implementation takes no screenshots or telemetry of that output. Terminal scrollback and user-created captures are outside Airodrom's retention control.

Governed browser research is **unavailable**. Natural research/navigation requests receive that status without navigating, creating a Mission, using credentials or inventing evidence. Public-page navigation, account authorization, human MFA takeover, domain policy, screenshot redaction and feature-gap/cost reports are unimplemented and unqualified. Arecibo comparison is explicitly unverified. Recommendations are never implemented automatically. This gate must remain closed until the complete capability is independently reviewed and qualified.

Validation uses synthetic identifiers and isolated disposition files, including the real Keychain helper with random synthetic references where available. Live personal Memory, Vault entries and Gmail authorization are preserved. Fixture checks do not establish live account or browser qualification. Integration follows [project governance](../GOVERNANCE.md) and [ADR 0012](adr/0012-natural-private-vault-and-research-gate.md).

Validated implementation: 90 targeted conversation, intent, secure-input, private-Vault, restricted-Memory, connector, Mission and diagnostic checks passed, with no skips. Earlier focused canonical erasure and existing assistant/Keychain checks also passed. Both declared typechecks, package allowlist and public syntax/source/link verification passed. Two independent privacy/authority reviews identified and verified repairs for multiline/whitespace private ingress, research admission, Unicode credentials and strict context/output handling; no material findings remain. The real macOS Keychain synthetic smoke saved a named mailbox identifier, reopened it in a separate process, retrieved it only after fresh confirmation, then revoked it; no value was exported. Broad hosted Actions remain manually disabled, and no live account/browser qualification is claimed.
